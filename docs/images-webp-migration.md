# Миграция загруженных фотографий в WebP

Работает с фотографиями JPEG, PNG, GIF, AVIF и WebP в `public/images/`, в том числе с неиспользуемыми сейчас файлами. Другие вложения (например, модели и документы) не меняются. Качество WebP — 95; размеры, прозрачность и анимация сохраняются, EXIF-ориентация применяется к пикселям.

Конфигурация берётся из `S3_*`. Путь к файлу переменных можно передать через `DOTENV_CONFIG_PATH`. Секреты не должны попадать в Git или вывод команд.

Предварительная проверка скачивает и конвертирует фотографии для подсчёта размеров, ничего не записывая:

```sh
DOTENV_CONFIG_PATH=.env.local pnpm exec tsx scripts/migrate-images-webp.ts
```

Создание копий и обновление ссылок:

```sh
DOTENV_CONFIG_PATH=.env.local pnpm exec tsx scripts/migrate-images-webp.ts --apply
```

Сначала создаются и побайтово проверяются все новые WebP-копии в подпапках `_webp-q95/`. Только затем в пользовательских `catalog.json` заменяются точные URL исходников, включая ссылки в компонентах и проектах. Посторонние URL, тексты, даты, порядок элементов и неизвестные поля сохраняются. Существующие файлы, созданные загрузчиком с метаданными `webp-quality=95`, пропускаются.

Перед каждой записью каталога создаётся и проверяется его побайтовая приватная копия в `migrations/webp-q95/{run}/users/{owner}/catalog.json`. Условная запись по ETag останавливает миграцию при конкурентном редактировании. В случае ошибки часть каталогов может быть уже обновлена; исходники остаются доступны, а повторный запуск использует те же WebP-копии и обрабатывает оставшиеся ссылки.

Приватный журнал `migrations/webp-q95/{run}/manifest.json` содержит исходные ключи и ETag, новые ключи, контрольные суммы, размеры, резервные копии и состояние обновления каждого каталога. В случае остановки после записи и до проверки статус каталога может оставаться `planned`: нужно сверить фактические ссылки. Путь к журналу выводится в конце выполнения и при ошибке.

**Исходники никогда не удаляются этой утилитой.** До удаления общий объём хранилища увеличится на размер новых копий. Итоговая экономия считается отдельно и для небольших или уже эффективно сжатых файлов может оказаться отрицательной.

После визуальной проверки можно отдельно согласовать удаление исходников по журналу. Перед таким удалением нужно заново проверить отсутствие ссылок в актуальных каталогах и совпадение ETag исходников. Для отката после новых пользовательских правок следует выполнить обратную замену URL по журналу с условной записью, сохранив текущие изменения. Полное восстановление старой копии каталога допустимо только если после миграции его никто не редактировал.
