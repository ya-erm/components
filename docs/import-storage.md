# Хранение данных импорта

`users/{userId}/catalog.json`, версия 2. Источник задаётся строкой в заказе, поэтому модель подходит и для других магазинов. Покупка ссылается на внутренний `order.id`, а сопоставление внешнего заказа использует пару `source + number`.

```json
{
  "version": 2,
  "orders": [{
    "id": "order-internal-id",
    "number": "1234567890",
    "source": "AliExpress",
    "store": "Electronics Store",
    "url": "https://example.com/orders/1234567890",
    "date": "Oct 12, 2026",
    "sourceStatus": "Completed",
    "totalText": "$12.50",
    "trackingNumbers": ["TRACK-1"],
    "trackingDetails": [{
      "trackingNumber": "TRACK-1",
      "carrier": "Post",
      "status": "Delivered",
      "lastEvent": "Received",
      "lastEventTime": "2026-10-20"
    }],
    "comments": [],
    "importState": { "exportedAt": "2026-10-21T12:00:00.000Z" }
  }],
  "items": [{
    "id": "component-id",
    "createdAt": "2026-10-13T12:00:00.000Z",
    "updatedAt": "2026-10-21T12:00:00.000Z",
    "data": {
      "name": "Моя плата",
      "images": [],
      "tags": ["ESP"],
      "comments": [],
      "inventory": [],
      "history": [],
      "usages": [],
      "purchases": [{
        "id": "purchase-id",
        "orderId": "order-internal-id",
        "quantity": 20,
        "status": "delivered",
        "productUrl": "https://example.com/products/board",
        "variant": "S3",
        "unitsPerPack": 10,
        "importState": {
          "exportedAt": "2026-10-21T12:00:00.000Z",
          "matchKey": "stable-product-and-variant-key",
          "lastQuantity": 20,
          "lastStatus": "delivered",
          "manualFields": []
        }
      }]
    }
  }],
  "shipments": [],
  "projects": []
}
```

`date`, `sourceStatus`, `totalText` сохраняют текст источника без выдуманной нормализации даты, суммы или валюты. `status` покупки — наш нормализованный статус. Необязательные поля могут отсутствовать.

`importState` — время последней выгрузки и защита повторного импорта. В покупке `matchKey` различает товары и варианты, `needsManualMatch: true` запрещает автоматическое сопоставление неполных/неотличимых позиций, `lastQuantity` и `lastStatus` содержат последние значения источника (количество уже в штуках). `manualFields` содержит `quantity` и/или `status`, которые исправлялись вручную. Названия, фото, теги, комментарии и использование остаются обычными данными компонента.

## Браузер

`import-preferences:v1:{userId}`:

```json
{
  "version": 1,
  "ignoredOrders": { "aliexpress": ["1234567890"], "other shop": [] },
  "migratedSources": ["aliexpress"]
}
```

Хранятся только номера, сгруппированные по источнику, без товаров и названий. Скрывается весь заказ. `migratedSources` предотвращает повторное скрытие восстановленного заказа при повторной доставке старых исключений. Черновик остаётся отдельно в `aliexpress-import:v1:{userId}`: исходный JSON, выбор, фильтры, незавершённые формы. Сырой JSON экспортера в черновике имеет формат исходного адаптера; в каталог целиком не записывается.

## Однократная миграция

Проверка: `pnpm exec tsx scripts/migrate-import-storage.ts`. Запись: та же команда с `--apply`. Подключение берётся из S3-переменных окружения, `dotenv/config` поддерживает `DOTENV_CONFIG_PATH`.

Утилита обходит пользовательские каталоги, переносит прежние вложенные метаданные в общие поля, сохраняет связи, ручные исправления и прежние названия заказов. Перед каждой записью создаёт и проверяет отдельную приватную копию в `migrations/import-storage/{run}/users/{userId}/catalog.json`. Запись условная по ETag; конкурентная правка останавливает миграцию, её можно повторить. После записи читается и проверяется результат. Повторный запуск не меняет уже перенесённые каталоги.

Старые исключения сворачиваются в необязательный временный `legacyIgnoredOrders: [{source, id}]`. Страница импорта сначала записывает их в браузер и только после этого подтверждает удаление из каталога. Если браузер или сеть недоступны, мост сохраняется. Новые исключения в S3 не пишутся. После передачи поля в каталоге нет.

Обычные схемы заказов и покупок больше не читают прежние вложения. Конвертация изолирована в утилите миграции, восстановлении старой резервной копии и однократном обновлении старого браузерного черновика. Обновлённую структуру нужно редактировать через новую версию приложения: старый деплой при перезаписи может отбросить незнакомые поля.
