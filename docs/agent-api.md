# API для агентов

В настройках `/settings` откройте «Доступ для агентов», укажите имя и срок
действия, выпустите токен и скопируйте его. Он показывается один раз.
Токен имеет полный доступ к каталогу владельца, включая удаление.
В настройках можно отозвать любой токен; по истечении срока он перестаёт работать.
В S3 сохраняется только SHA-256 токена, не его исходное значение.

Передайте агенту адрес приложения и токен через секрет его окружения.
Все запросы используют `Authorization: Bearer <token>`; cookie и вход в браузере
агенту не нужны. Токены нельзя передавать через query-параметры URL.

```sh
export COMPONENTS_URL='https://your-components.example'
# COMPONENTS_TOKEN задаётся через секреты окружения
curl "$COMPONENTS_URL/api/agent"
curl -H "Authorization: Bearer $COMPONENTS_TOKEN" \
  "$COMPONENTS_URL/api/components?q=ESP32&all=1"
curl -X POST -H "Authorization: Bearer $COMPONENTS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"data":{"name":"ESP32-S3","purchases":[],"usages":[]}}' \
  "$COMPONENTS_URL/api/components"
curl -X PATCH -H "Authorization: Bearer $COMPONENTS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"data":{"note":"Ящик 3"}}' \
  "$COMPONENTS_URL/api/components/COMPONENT_ID"
```

`GET /api/agent` — публичный машиночитаемый справочник всех операций, моделей,
ограничений, кодов ошибок и примеров. Персональных данных в нём нет.
Агенту достаточно прочитать этот адрес перед началом работы.

Поддерживаются поиск и фильтры, создание/чтение/изменение/удаление компонентов,
закупки и использование по проектам, комментарии, старые остатки и история,
заказы и трекинг, проекты, изображения, полный экспорт и импорт JSON,
анализ/предпросмотр/применение импорта AliExpress. Карточки возвращаются полностью,
включая метаданные импорта. `GET /api/logistics` возвращает связанные сущности,
`PATCH /api/logistics` позволяет создавать и обновлять их независимо от карточки.

`PATCH /api/components/{id}` меняет только переданные поля `data`. Переданный
массив заменяет весь предыдущий массив. Перед добавлением комментария, закупки
или использования прочитайте карточку, сохраните все прежние элементы и их id.
Для защиты от изменений между чтением и записью передайте заголовок `ETag`
из GET как `If-Match` в PATCH. При 409 перечитайте карточку и повторите изменение.
`PUT` заменяет всю `data`, а импорт объединяет записи по id, не удаляя отсутствующие.

Заказ или проект можно добавить в `logistics` одновременно с изменением карточки:
связи и остатки проверяются в одной записи. Доставленные закупки увеличивают
остаток, `usages` расходуют его. Неизвестное количество пропускайте; ноль означает
известное отсутствие. Новые записи создавайте со стабильными UUID.

Токен не позволяет выпускать другие токены. API управления токенами
`/api/settings/tokens` доступно только с браузерной сессией; изменения требуют
same-origin запроса. Данные другого пользователя недоступны, даже если известен id.
Настройки исключений импорта и незавершённые черновики, которые интерфейс хранит
в localStorage браузера, не являются серверными данными; агент может вести свои
правила отбора локально, отправляя выбранные строки импорта.

Новых переменных окружения или миграций не требуется. Индексы токенов хранятся
в приватном префиксе `api-tokens/` того же бакета. Публичная политика бакета
должна разрешать только `public/images/`, как и при обычной работе приложения.
