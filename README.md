# Склад компонентов

Веб-приложение для учёта электронных компонентов на складе. Mobile-first, у каждого пользователя свой каталог. Карточки в стиле маркетплейса, фото и данные в S3-совместимом хранилище.

## Стек

- **Next.js 15** (App Router), React 19, TypeScript
- **Tailwind CSS v4**
- **S3-совместимое** хранилище (AWS S3 / Yandex Cloud / MinIO) — для фото **и** пользовательских данных
- **Auth.js v5 (NextAuth)** — вход по логину/паролю (Credentials + JWT)

## Модель данных

Все данные хранятся в S3 (без базы данных):

| Ключ | Содержимое |
| --- | --- |
| `users/index.json` | `{ byLogin: {…}, byId: {…} }` — все пользователи |
| `users/{userId}/catalog.json` | каталог v2: компоненты, общие заказы и проекты |
| `public/images/{userId}/{uuid}.ext` | загруженные фото (публичный доступ) |

Набор полей компонента фиксирован в `lib/schema.ts`: `name`, `images[]`, `purchases[]`, `usages[]`, `comments[]`, `type`, `tags[]`, `note`, `url`.

В разделе «Заказы» каждая запись `purchases` содержит количество и статус: «Запланировано», «В пути», «Доставлено», «Отменено». Отменённые позиции не увеличивают остаток. Название или номер вводится один раз; трек-номер виден в одном поле без раскрытия. Ранее сохранённые несколько треков остаются в этом поле через запятую. Ссылка и комментарии доступны в раскрываемом блоке. Новый заказ создаётся непосредственно у компонента, без выбора из списка. Существующие связи между компонентами и общими заказами (`orders`) сохраняются для совместимости. Статус и количество относятся к позиции компонента, поэтому части одного заказа могут быть доставлены в разное время.

В разделе «Использование» запись `usages` содержит проект и использованное количество. Проекты (`projects`) общие для каталога; страница `/projects` показывает все компоненты, использованные в каждом проекте. Проект создаётся при добавлении использования и затем доступен у остальных компонентов.

### Проекты: порядок и выбор компонентов

На `/projects` проекты можно перетаскивать за ручку ⠿. На странице проекта так же меняется порядок используемых компонентов. Порядок сохраняется в каталоге S3, доступен на других устройствах и включён в экспорт. Мышь и касания работают за ручку; для клавиатуры: пробел, стрелки, пробел для завершения или Escape для отмены. Остальная часть списка остаётся доступной для прокрутки.

Кнопка «Выбрать компоненты» на странице проекта открывает полноэкранный каталог с той же сеткой карточек, поиском, фильтрами, группировками и переключателем вида, что на главной странице. Нажмите на карточки, задайте использованное количество под выбранными компонентами и нажмите «Сохранить компоненты». Пустое количество остаётся неизвестным. Повторное нажатие снимает выбор и удаляет только использование в текущем проекте; сам компонент и его использования в других проектах сохраняются. Счётчик учитывает и выбранные компоненты, скрытые фильтрами. «Отмена» и Escape не записывают изменения. Выбор скрытых поиском компонентов сохраняется.

Записи использования остаются общими для страницы компонента и страницы проекта. Неизменённые составные записи (включая частично неизвестное количество) сохраняются без потери данных. Проверка остатка выполняется на сервере до атомарной записи. При параллельном изменении состава проекта сервер отклоняет устаревший выбор, предлагая обновить страницу. Условные S3-записи не позволяют параллельным операциям затереть посторонние изменения каталога.

`node tests/projects-api-fixture.mjs` проверяет новые API на локальном тестовом сервере из раздела ниже: порядок, количество, экспорт/импорт, конфликты и изоляцию пользователей. Это не проверка реального устройства; перетаскивание на iPhone следует проверить на стенде.

Доступный остаток вычисляется как доставленное количество минус использованное. Запланированные заказы и заказы в пути его не увеличивают. Сохранение не допускает использование сверх известного доставленного количества. Пустое количество означает неизвестное; такие записи не превращаются в ноль. Карточки и фильтры отдельно показывают остаток, путь, планы и использование.

Старые форматы поддерживаются: складские и использованные количества становятся доставленными заказами, использование привязывается к общим проектам по названию. Треки старых посылок переносятся в заказы. Исходные `inventory`, `history`, `shipments` сохраняются как архив, без отдельных полей посылки в интерфейсе. Противоречивые старые состояния требуют уточнения. Преобразование выполняется при чтении и сохраняется при следующей записи; экспорт включает новые записи и архив, импорт проверяет связи и остаток до записи.

## Импорт из AliExpress

Импорт открывается из настроек по кнопке «Импорт из AliExpress» (`/components/import/aliexpress`). Загрузите JSON экспортера версии схемы 1 (до 4 МБ), выберите заказы или отдельные товары, сопоставьте их с компонентами и проверьте изменения перед сохранением. При каждой загрузке файла все галочки сняты. Заказы отсортированы от новых к старым; доступны поиск, фильтр по дате и признаки «Новый», «Есть изменения», «Без изменений», «Нужно уточнить». Выбор не пропадает при фильтрации, счётчик включает скрытые выбранные товары.

Можно создать компонент, добавить новую покупку существующему компоненту или связать товар с покупкой, уже внесённой вручную. Для упаковок задаётся число штук: 2 упаковки по 10 дают 20 компонентов. Покупка связана с обычным заказом через `purchase.orderId`; данные товара, заказа и доставки хранятся в общих полях, служебные — в `importState`. [Структура и миграция](docs/import-storage.md).

В фильтре «Показать» можно отметить несколько категорий одновременно, например «Новый» и «Есть изменения». Позиция показывается при совпадении с любым выбранным пунктом. «Скрытые» можно сочетать с остальными категориями; по умолчанию скрытые исключены. «Все позиции» сбрасывает фильтр. Множественный выбор сохраняется в черновике; прежний одиночный фильтр восстанавливается без потери настроек.

Ссылка «Заказ ↗» открывает заказ, а «Товар ↗» у каждой позиции — соответствующую страницу товара AliExpress. Обе открываются в новой вкладке. Если ссылки товара нет в выгрузке, она не показывается.

Новый компонент заполняется в полной форме каталога: фото, тип, теги, ссылка, заметка, комментарии, покупки и использование. Выбор существующего компонента открывает полноэкранный каталог с поиском, фильтрами, группировками и тремя видами отображения. В уже привязанных позициях видна настоящая карточка компонента с фото, названием, тегами и остатками; её можно открыть в новой вкладке.

Черновик импорта автоматически сохраняется в `localStorage` этого браузера отдельно для аккаунта (`aliexpress-import:v1:{userId}`). Он содержит исходную выгрузку, выбор товаров, фильтры, привязки и незавершённые формы новых компонентов. Возврат «Назад»/«Вперёд», перезагрузка и закрытие вкладки не сбрасывают черновик. Видны время сохранения и кнопка «Удалить черновик». Другой JSON начинает новый черновик со снятыми галочками; ошибка загрузки сохраняет предыдущий. При недоступном или переполненном хранилище показывается предупреждение. На другом устройстве черновик недоступен.

Кнопка «Применить этот товар» сразу сохраняет только настроенную позицию, остальные остаются в черновике. Перед записью автоматически выполняется проверка предпросмотра с теми же ограничениями и защитой от конфликтов, что и при общем импорте. Также можно проверить и применить все выбранные товары вместе.

Предпросмотр показывает карточки результата, счётчики и короткие изменения «было → станет» для количества, статуса и треков. Подробности доставки раскрываются отдельно. Неизменившиеся карточки собраны в раскрываемую группу.

Кнопка «Больше не показывать заказ» сразу скрывает весь заказ. В `localStorage` (`import-preferences:v1:{userId}`) сохраняются только номера скрытых заказов по источникам. Запросов в S3 и очереди сохранения нет; при ошибке браузерного хранилища видимость не меняется. Вернуть заказ можно через фильтр «Скрытые». Исключения переживают замену JSON, удаление черновика и повторные импорты в этом браузере; на другом устройстве и в резервной копии каталога их нет.

Номер хранится в обычном `orders[].number`, источник — в `orders[].source`. Импорт сначала находит наш заказ по источнику и номеру, затем покупки по `purchase.orderId` этого заказа. Если в заказе одна позиция и одна покупка без импортных метаданных, они сопоставляются автоматически. Для нескольких позиций дополнительно учитываются товар и вариант, независимо от порядка строк и рекламных параметров URL. Прежнее название вручную связанного заказа сохраняется комментарием. Рядом с «Есть изменения» показаны конкретные переходы количества, статуса, треков и других полей; учитываются фактически применяемые изменения с сохранением ручных исправлений.

Повторная загрузка не прибавляет количество повторно и не создаёт дубль. Неполные и повторяющиеся позиции требуют ручного сопоставления при каждой загрузке: индекс строки служит только для выбора в текущем файле, автоматическая привязка по нему не выполняется.

Автоматическое обновление сохраняет названия, заметки, теги, изображения, комментарии, проекты и ручные исправления количества/статуса. Пустые значения не стирают известные; старые выгрузки не обновляют данные автоматически. Треки объединяются, сведения из кэша только заполняют пустой список. `Completed` означает доставленную покупку, `Awaiting delivery` — покупку в пути, `Canceled` — отменённую; неизвестный статус требует уточнения. Статус покупки можно выбрать вручную в импорте. Обратный переход из доставленного или отменённого состояния автоматически не выполняется. Подробности перевозчика и последнего события видны в предпросмотре, в том числе если они расходятся со статусом заказа.

Анализ и предпросмотр ничего не записывают. Применение повторно сравнивает каталог с предпросмотром и использует условную запись S3 по ETag; конфликт возвращает 409 и требует нового предпросмотра. Все выбранные изменения проходят проверку связей и остатков до одной записи каталога. S3-хранилище должно поддерживать `If-Match` / `If-None-Match`.

`pnpm test` проверяет повторные выгрузки, варианты, упаковки, ручные правки, неполные данные и совместимость экспорта. `node tests/aliexpress-api-fixture.mjs` проверяет новый API на локальном тестовом S3 и пользователе `fixture-demo`, включая конфликт предпросмотра и условную запись. Для этих проверок используйте только тестовый dev-сервер, описанный ниже.

## Быстрый старт (локально)

Нужны Node.js 20+ и Docker.

```bash
# 1. Поднять MinIO (S3-совместимое хранилище)
docker-compose up -d

# 2. Переменные окружения
cp .env.example .env
# Заполни S3_* и AUTH_SECRET (openssl rand -base64 32)

# 3. Зависимости
pnpm install

# 4. Залить демо-данные в S3
pnpm db:seed    # пользователь demo / пароль demo12345 + 32 компонента

# 5. Запуск
pnpm dev        # http://localhost:3000
```

Демо-аккаунт: **логин `demo`, пароль `demo12345`** (или зарегистрируйте свой).
Консоль MinIO: http://localhost:9001 (`minioadmin` / `minioadmin`).

## Скрипты

| Команда | Действие |
| --- | --- |
| `pnpm dev` | дев-сервер |
| `pnpm build` | прод-сборка |
| `pnpm start` | запуск прод-сборки |
| `pnpm typecheck` | проверка типов |
| `pnpm test` | проверки миграции, остатков и перемещений |
| `pnpm db:seed` | записать демо-данные в S3 |

Для проверки без рабочего S3 есть `tests/s3-fixture.mjs`: локальное хранилище в памяти, порт 19000, пользователь `demo / demo12345`. Команда запуска dev-сервера с тестовым бакетом указана в начале файла. `node tests/api-fixture.mjs` проверяет общие заказы и проекты, остаток, фильтры, валидацию и повторный импорт. Проверка требует именно тестового пользователя и каталога; данные исчезают при остановке хранилища.

## Переменные окружения

См. `.env.example`. Ключевые:

- `AUTH_SECRET` — секрет Auth.js (`openssl rand -base64 32`).
- `S3_ENDPOINT` — пустой для AWS; для YC: `https://storage.yandexcloud.net`; для MinIO: `http://localhost:9000`.
- `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`.
- `S3_FORCE_PATH_STYLE` — `true` для MinIO/YC.
- `S3_PUBLIC_URL` — базовый URL для публичных фото (без слеша); хост добавляется в `images.remotePatterns`.

## Загрузка изображений

Файлы льются на сервер через `POST /api/upload` (по одному — лимит ~4.5 МБ serverless), сохраняются под `public/images/...` в S3. До 10 фото на компонент. Превью через `next/image`.

## S3: публичность и безопасность

Политика бакета открывает анонимное чтение **только на `public/*`** (фото). Пользовательские данные (`users/*`) приватны и читаются только с сервера по ключам SDK. Шаблон политики: `infra/yc-bucket-policy.json`. Подробнее: `infra/README.md`.

## Деплой на Vercel

1. Публичный GitHub-репозиторий (`.env` в `.gitignore`).
2. В Vercel задать переменные: `AUTH_SECRET`, `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_FORCE_PATH_STYLE`, `S3_PUBLIC_URL`.
3. Build command: `pnpm build` (без миграций — БД нет).
4. После первого деплоя запустить сид: `pnpm db:seed` локально с прод-переменными (или добавить как release command).

## Безопасность

- Пароли хешируются (bcrypt), хранятся в `users/index.json` в приватной части S3.
- Все страницы и API закрыты авторизацией (`middleware.ts`).
- Каталог компонентов скоуплен по `ownerId` — чужой каталог недоступен.
- Секреты только в `.env` / Vercel env vars.
